comic-dl-web は comic-dl の単一ユーザー向けセルフホスト Web UI です。ダウンロードと更新確認はサーバーで実行され、管理者が指定したディレクトリへ直接保存します。ブラウザーは漫画ファイルを転送せず、オンラインリーダーでもありません。ページを閉じてもバックグラウンド処理は続きます。

このページは WebUI を開けるユーザー向けです。サービスの導入、環境変数、バックアップは[デプロイ](../deployment/)をご覧ください。

## ログインと表示

管理者パスワードが有効な場合、業務ページ、API、表紙、リアルタイムイベントへのアクセスにはログインが必要です。通常はブラウザーのセッション Cookie を使用し、「ログイン状態を保持する」を選ぶと 30 日間保存します。サーバー側の有効期間も最大 30 日です。サービスを再起動すると全ログインが無効になります。ブラウザーがセッション Cookie を復元することもあるため、共有端末では設定から明示的にログアウトしてください。

ヘッダー、設定、ログインページで中国語・English・日本語を切り替えられます。言語 Cookie はそのブラウザーで 1 年間保存されます。翻訳するのはアプリ自身の文言だけで、作品名、章名、作者、あらすじ、タグ、配信元が定義したフィルターや項目は原文のままです。切り替えると現在の URL を再読み込みしますが、サーバーの処理は中断しません。

設定ではライト・ダーク・システム連動を選べます。表示設定はブラウザーに保存されます。ホームは本棚で、詳細／コンパクト表示を切り替えられます。コンパクト表示では管理アイコンから全操作を開きます。

## 閲覧と検索

1. 配信元の一覧から CopyManga、Zerobyw、DM5、Komga、Kavita を選びます。
2. 空のキーワードで閲覧するか、検索語を入力します。並べ替え、絞り込み、ページ分割は配信元によって異なり、検索では閲覧時の項目を使えない場合があります。
3. 横断検索の結果は配信元別に表示されます。一部の配信元が利用できなくても、他の結果は確認できます。
4. 作品を開き、表紙、メタデータ、あらすじ、章を確認して、本棚への追加やダウンロードを行います。

表示できる情報は配信元によります。表紙がないことだけでダウンロード不可とは限りません。サイトの利用規約、地域制限、通信状態、アカウント権限は引き続き適用されます。

### 配信元の認証情報

Web 管理は初期状態で無効です。管理者が有効にすると、配信元設定で通常項目と内蔵アダプターの認証情報を保存できます。保存した秘密情報は再表示しません。

| 配信元    | 注意点                                                                                                                                                                                                                                      |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CopyManga | 匿名で閲覧可能。サイト、API、User-Agent は配信元設定で指定します。                                                                                                                                                                          |
| Zerobyw   | 閲覧／検索は匿名で可能ですが、章一覧とダウンロードには有効な Cookie が必要です。ログインリンクを別タブで開き、開発者ツールのネットワーク画面から作品リクエストの `Cookie` ヘッダーをコピーできます。公開 Issue や画像に含めないでください。 |
| DM5       | 公開コンテンツを利用できます。現在の内蔵アダプターには編集項目がありません。                                                                                                                                                                |
| Komga     | サーバー URL と API Key を指定します。                                                                                                                                                                                                      |
| Kavita    | サーバー URL と Auth Key を指定します。                                                                                                                                                                                                     |

Web の認証情報は保存時の配信元アドレスに結び付けられます。アドレス変更後は保存し直してください。削除するとデプロイ環境の認証情報に戻ります。「初期値に戻す」は通常設定だけをリセットします。内蔵版を上書きする管理対象拡張には Web の認証情報を渡しません。拡張の説明に従って管理者が設定してください。

## 本棚と自動更新

作品詳細、または本棚のリンク追加フォームから登録します。同一配信元・同一作品は重複登録せず、別配信元の版は独立します。

- 作品名を開くと章を選べます。「未ダウンロードの章をすべてダウンロード」はコアが既存アーカイブを検証する操作で、事前にローカル章一覧を表示する機能ではありません。
- 更新確認は単一作品、全作品の確認は自動確認を無効にした作品も対象にします。
- 自動確認は定期的な目次取得、自動ダウンロードは新しく発見した章のキュー登録を制御します。二つは独立しています。
- 自動追跡の開始／一時停止のショートカットは両方を切り替えます。
- 作品の確認間隔が空欄なら全体設定に従います。全体設定の変更は作品固有の間隔を上書きしません。

### 初回確認でダウンロードされない理由

初回成功時は通常、目次の基準だけを記録します。本棚全体を意図せずダウンロードしないためです。既存の章が必要なら、履歴のダウンロードか手動選択を使ってください。

自動ダウンロードが無効な間の新章は、発見済みの章として残り、手動でキューに追加できます。後から有効にしても、以前の発見分は**遡って自動登録されません**。手動確認も自動ダウンロード設定に従います。

スイッチを無効にしても登録済みタスクは取り消されません。キャンセルは明示的に操作してください。失敗／制限された章は通信や権限の問題を解決後に再試行できます。本棚から削除してもアーカイブは残ります。作品入力の編集先も同一配信元・同一作品でなければなりません。

## 手動ダウンロードとタスク

手動ダウンロードで作品リンクや短い ID を入力し、必要なら配信元を選んで章一覧を取得します。章の選択または両端を含む範囲（例：`2-4`）を指定します。対応する章の直リンクも使用できます。送信時に目次を検証するため、変更されていた場合は選び直してください。

右上のダウンロード管理では、手動と watcher のタスクを配信元・作品別に表示し、章番号、処理段階、ページ進捗、結果を確認できます。キャンセル、再試行、終了記録のクリアに対応します。

- 既存ファイルは名前ではなく、識別情報と完全性を検証してスキップします。
- 一章の失敗が他の結果を隠すことはありません。再試行は現在の設定で対象となる章だけを処理します。
- スナップショットは実行中と一定数の最近の記録に制限され、全章の結果はページ単位で取得します。
- 記録のクリアはアーカイブや本棚の履歴を削除しません。watcher の記録は現在のプロセスでのみ非表示になります。
- 手動キューと履歴は再起動で失われます。完成したファイルは残り、再送信時に検証済みのものをスキップします。
- watcher のキューは永続化します。リアルタイムのページ数は保存せず、新しい試行では数え直します。

アクセスとバックアップの権利があるコンテンツだけを取得してください。ファイルはサーバーに保存され、端末へ自動転送されません。外部リーダー、Komga、Kavita などから漫画ディレクトリを読み取ってください。

## アーカイブ設定と移行

Web 管理が有効なら、設定で既存の出力サブディレクトリ、確認間隔、既定の配信元、アーカイブ方針を変更できます。サブディレクトリは出力ルート内にあらかじめ存在し、シンボリックリンクでないことが必要です。変更しても既存ファイルは移動しません。

既定は `{title}/{number}-{chapter}.cbz` です。CBZ／ZIP、番号のゼロ埋め、ファイル名を含め最大 4 個のパス要素からなるテンプレートに対応します。変数は `{title}`、`{number}`、`{chapter}`、`{workId}`、`{chapterId}` で、拡張子は付けません。章番号は選択した範囲ではなく目次全体に基づきます。直リンクの文脈が不足する場合は章 ID にフォールバックします。

テンプレート、形式、配信元の並び順を変更しても自動改名しません。既存の完全なアーカイブは安定した識別情報で認識します。改名が必要な場合：

1. 管理者がバックアップし、他の CLI、同期ツール、リーダーの書き込みを停止します。
2. 手動タスクを完了またはキャンセルします。
3. 設定のアーカイブ移行で単一作品または本棚全体のプレビューを確認します。
4. 明示的に適用します。既存の移行先は上書きしません。一括トランザクションではないため、失敗時は部分的な結果を確認してから再プレビューしてください。

プレビューは 10 分間有効で、設定変更や再起動後は作り直します。適用中は watcher を一時停止し、新規手動タスクを拒否します。移行は保存パスの変更であり、DB バックアップや内容形式の変換ではありません。

## 拡張管理

マーケットは内蔵の推奨配信元と実際の読み込み状態を表示します。管理者が有効にした場合、npm パッケージ名とバージョン範囲／タグを指定して管理対象拡張を導入できます。拡張はサーバーと同じ権限で実行されるコードです。信頼できるパッケージだけを使ってください。

同じ配信元では管理対象版が内蔵版より優先され、削除すると内蔵版へ戻ります。内蔵依存は Web イメージと一緒に更新され、管理対象版は別に管理します。

更新確認だけではインストールせず、確認後に適用します。適用時に保存した範囲を再解決するので、確認結果はバージョン固定ではありません。固定バージョンは自動更新されず、`^0.2.0` に `0.3.0` は含まれません。範囲を跨ぐ場合は新しい範囲やタグを明示してください。定義の読み込み成功は、サイトやアカウント、ダウンロードの動作保証ではありません。

## アプリとしてインストール（PWA）

HTTPS でサービスを開いてから操作します。

- Chrome／Edge：アドレスバーやメニューのインストール。
- iPhone／iPad：ブラウザーの共有メニュー → ホーム画面に追加。
- macOS Safari：Dock に追加。

入口は OS／ブラウザーによります。通常の HTTP LAN IP は一般に対象外で、開発用 localhost／127.0.0.1 は例外です。

既存のプロジェクトアイコンを使い、独立ウィンドウで本棚を開きます。インストール後もログインとサーバー接続が必要です。Service Worker、オフラインキャッシュ、オフライン閲覧はありません。

## よくある問題

| 症状                       | 確認事項                                                                                             |
| -------------------------- | ---------------------------------------------------------------------------------------------------- |
| 新章が取得されない         | 基準作成、自動ダウンロード設定、失敗／制限の結果を確認。過去の発見分は手動登録が必要です。           |
| 出力が利用できない         | 管理者がマーカーや選択ディレクトリを復旧します。watcher は待機するため繰り返し送信しないでください。 |
| 配信元や表紙が利用できない | URL、認証、通信、内蔵版／管理対象版のどちらが有効かを確認します。                                    |
| 進捗が止まる               | 再接続／再読み込みでスナップショットを取得。管理者が SSE のバッファーとタイムアウトを確認します。    |
| watcher のロック競合       | 同一本棚の watcher は一つだけです。他のインスタンスを停止します。                                    |
| 再起動後にログインが必要   | ログイン状態はサービスのメモリー内にのみ保存するため、正常な動作です。                               |
