---
title: 3.x から 4.x への移行
description: 本棚自動化、読みやすいアーカイブ、Web バックエンド API への移行。
---

`comic-dl@latest` 導入前に watcher を止め、本棚 SQLite DB をバックアップしてください。Node.js 24 と拡張機能の `apiVersion: 1` は変更ありません。4 は本棚 v1/v2 をトランザクション内でスキーマ v3 に更新します。旧コアでは開けないため、戻すにはバックアップを復元します。

- 旧 `following=1` は自動確認・ダウンロード両方有効、`0` は両方無効に対応します。基準・既存タスク・失敗・完了結果は維持されます。
- `shelf check` は自動化無効の項目も含む本棚全体を確認します。`follow/unfollow` は両設定を切り替えますが既存タスクを中断しません。`shelf configure <id> --auto-check on --auto-download off --interval 1800` で独立設定できます。
- 既定アーカイブは平坦なハッシュ名ではなく `{作品名}/{正規番号}-{チャプター名}.cbz` です。`archive` でテンプレート・ゼロ埋め・CBZ/ZIP を設定します。3.x の識別マーカー付きアーカイブは検査してスキップされ、自動改名しません。2.4.0 の歴史的比較は [2.x 移行](../v2-to-v3/)を参照してください。
- メタデータのない旧拡張機能は作品 ID を表示します。正規目録のコンテキストがない直リンクは番号不明で、名前にチャプター ID を使います。完全な情報には拡張機能を更新してください。任意メタデータの欠落で旧拡張のダウンロードは妨げられません。
- 既存結果はサーバースクリプト向けです。Web は `onResult` のパス・診断を送信せず、安全なスナップショットと `onEvent` を使います。
- NAS ルートマーカーと既存保存サブディレクトリは `outputRoot` で分離します。CLI は `--output-root /mnt/comics -o /mnt/comics/Manga --require-output-marker .nas-ready` です。

契約全体、中断・再試行、明示的移行、拡張更新プレビューは [Web バックエンドとタスク API](../../guide/service-api/)を参照してください。

4.1.0 は CLI に `extensions`、`update --check`、`migrate/--apply`、`list --details`、`search --json`、アーカイブ設定、手動 NAS 保護、ページ進捗を追加します。4.0 からの更新では本棚スキーマの再変更や互換 API v1 拡張の再導入は不要です。移行前に書き込みを止めてバックアップし、改名はプレビューの明示適用でのみ行ってください。[CLI リファレンス](../../reference/cli/)と[機能比較](../../guide/library/#機能対応と-web-要件)を参照してください。
